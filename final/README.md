# Итоговое задание: «Статистика температуры»

Приложение подготовлено на основе согласованной версии задания 13 (`temperature_lesson13_aligned_with_11_12.zip`) и проверено по документу «Итоговое задание.pdf» и двум предоставленным CSV. Преемственность: лекция 11 — тип записи и шесть заглушек; лекция 12 — реальные вычисления и фиксированный массив; лекция 13 — динамический буфер; итоговое задание — соответствие ТЗ, проверка на исходных данных и усиление обработки ошибок.

## Сборка и запуск

Нужны GCC и make. Примеры для Linux, WSL или совместимой среды. Исходники и сообщения используют UTF-8.

```sh
make
./prog -h
./prog -f temperature_small.csv
./prog -f temperature_small.csv -m 1
./prog -f temperature_big.csv -e big_errors.log
./prog -f temperature_big.csv -m 2 -e february_errors.log
make clean
```

Команды выполняются из распакованного каталога проекта. Можно передать абсолютный путь к CSV; пути с пробелами заключаются в кавычки. Имя `prog` сохранено из задания 11.

Для повторного запуска с `-e` укажите новое имя журнала. Если такой файл уже существует, программа завершится с ошибкой, сохранив его содержимое. Можно также не указывать `-e` и перенаправить стандартный поток ошибок средствами командной оболочки:

```sh
./prog -f temperature_big.csv 2> diagnostics.txt
```

## Аргументы

| Ключ | Назначение |
|---|---|
| `-h` | Описание программы и поддерживаемых ключей |
| `-f FILE` | Входной CSV |
| `-m MONTH` | Только три показателя выбранного месяца, номер 1–12 |
| `-e LOG` | Создать новый журнал с номерами и причинами всех ошибочных строк; на экране оставить сводку |
| `-i` | Дополнительное интерактивное меню работы с записями |

Без `-m` выводятся три показателя для каждого из 12 месяцев и три показателя за год. Месяцы без измерений отображаются как «нет данных». Подпись года и число загруженных записей не являются годовой статистикой и остаются при `-m`.

Фильтр `-m` применяется к выводу статистики. Весь входной файл проверяется даже при выборе одного месяца; ошибки остальных месяцев также сообщаются.

Сохранён ручной разбор `argc`/`argv`, использованный в согласованных версиях 12 и 13. Ключи и значения задаются отдельными аргументами: `-m 1`, а не `-m1`. Дополнительные `-e` и `-i` не заменяют обязательные `-h`, `-f`, `-m`.

## Формат CSV

```text
YEAR;MONTH;DAY;HOUR;MINUTE;TEMPERATURE
2021;01;16;01;01;-47
```

Заголовок необязателен. В первой строке поддерживаются приведённый заголовок и такой же заголовок в нижнем регистре. Допускается UTF-8 BOM в начале файла.

Поля числовые, разделитель — `;`. Числа с ведущими нулями и пробелами принимаются. Это необходимо для двух предоставленных файлов: малый использует `01`, большой — пробелы и однозначные числа. При сохранении месяц, день, час и минута печатаются через `%02d`, год — через `%04d`.

Проверяются диапазоны года 1–9999, месяца 1–12, часов 0–23, минут 0–59, температуры −99…99, а также календарный день с учётом високосного года. Файл должен содержать измерения одного года: год определяется первой корректной записью, строки другого года отклоняются.

Пустые строки пропускаются. Поддерживаются LF, CRLF и последняя строка без завершающего LF. Нулевой байт внутри строки не должен скрывать её оставшееся содержимое: вся такая строка отклоняется. Числа разбираются по цифрам с проверкой границы до умножения и сложения. Лишние поля, нечисловые значения и посторонний текст после шестого поля отклоняются.

Буфер строки имеет размер 256 байт. Строка может содержать до 255 байт до LF; более длинная строка дочитывается целиком и отклоняется с указанием номера. Это ограничение длины текстовой записи, а не числа измерений. Обычные строки предоставленных файлов значительно короче.

Для ошибок CSV всегда сохраняются физические номера строк, начиная с 1. Заголовок и пустые строки тоже учитываются при нумерации. Например, в малом файле ошибочной является строка 4.

## Обработка ошибок и журнал

Без `-e` каждое сообщение с номером строки выводится в `stderr`, после чтения показывается общее количество пропущенных записей. С `-e` все эти сообщения сохраняются в журнале, а в `stderr` выводятся общий счётчик и путь к журналу. Номера не обрезаются до первых нескольких ошибок.

Журнал открывается в режиме C11 `wx`: создание только нового файла. Поэтому существующий журнал, исходный CSV и его существующие ссылки не перезаписываются через `-e`. Пустой журнал допустим, если ошибок в CSV нет. Ошибка открытия или записи журнала приводит к неуспешному завершению, а не к молчаливой потере диагностики. При неудачной обработке созданный журнал может содержать сообщения уже прочитанной части файла.

Если хотя бы одна корректная запись загружена и не было ошибки ввода-вывода/памяти, программа рассчитывает статистику по принятым записям и возвращает 0. Наличие пропущенных ошибочных строк само по себе не останавливает расчёт.

Ошибки аргументов, открытия/чтения файла, журнала, выделения памяти, достижение предела размера, а также отсутствие корректных записей при загрузке приводят к ненулевому коду завершения. При отказе загрузки частичная статистика не выводится, выделенная память освобождается.

## Динамическое хранение

```c
typedef struct {
    TemperatureRecord *data;
    int size;
    int capacity;
} TemperatureArray;
```

Тип `TemperatureRecord` и его шесть полей `int` сохранены из задания 11. В контейнере `size` — число записей, `capacity` — число выделенных мест. `create_array()` создаёт пустое состояние без выделенного буфера. При добавлении `grow_array()` выделяет 8 мест, затем удваивает вместимость по необходимости.

`realloc()` вызывается через временный указатель: при отказе предыдущие записи и адрес остаются действительными. Перед увеличением размера проверяются границы `int` и `size_t`. Буфер освобождается через `free_array()` при нормальном выходе и ошибке загрузки. Удаление сдвигает элементы и уменьшает `size`, но сохраняет вместимость для повторного использования.

Предел 600000 из версии 12 не возвращён. Размер ограничен доступной памятью и представимостью счётчиков/размера блока. В тестах загружается 600001 запись. Это не обещание неограниченного размера входного файла.

## Статистика и меню

Шесть функций `print_month_average`, `print_month_min`, `print_month_max`, `print_year_average`, `print_year_min`, `print_year_max` сохраняют параметры и тела из версии 13. Каждая функция учитывает нужный год; месячные функции дополнительно отбирают месяц.

Средняя — сумма принятых измерений, делённая на их число. Сумма имеет тип `long long`, перед делением выполняется преобразование к `double`. Отсутствующие измерения не заменяются нулями. Среднее за год рассчитывается по всем измерениям, а не как невзвешенное среднее двенадцати средних за месяц.

Повторяющиеся отметки времени не удаляются автоматически. В ТЗ не задано правило объединения таких записей, а в его примере одна отметка повторяется. Каждая корректная строка учитывается как отдельное измерение.

Меню `-i` сохраняет добавление, удаление, сортировку, печать, сохранение, повторный расчёт статистики и выход. Для добавления вводятся шесть чисел через пробел. Номера записей в меню начинаются с 1, индексы массива — с 0. Другой год нельзя добавить в непустой массив. После удаления всех записей новую запись можно добавить с другим годом.

Пункт 5 меню **перезаписывает входной CSV текущим массивом**, как в версиях 12 и 13; для экспериментов используйте копию. Выход без выбора пункта сохранения не меняет CSV. Сохранение пустого массива создаёт файл только с заголовком; следующая загрузка сообщит об отсутствии измерений.

## Необязательное тестирование

```sh
python3 verify.py
```

Нужны Python 3, GCC с UndefinedBehaviorSanitizer и GNU-совместимый линковщик с поддержкой `--wrap`. Для обычной сборки и запуска Python и тестовый линковщик не нужны.

Проверки используют временный каталог и не меняют комплектные CSV. `test_memory.c` искусственно вызывает отказ первого выделения и последующего расширения, проверяет сохранность старых записей и освобождение буфера на путях завершения `main()`. Этот тестовый механизм не является частью учебного приложения.

Подробное сопоставление с ТЗ — в `CHANGES_FINAL.md`, результаты по обоим исходным CSV — в `TEST_RESULTS.md`.
